# Настройка Supabase

Миграция находится в `supabase/migrations/001_initial_schema.sql`. Она создаёт таблицы `students`, `attempts`, `attempt_answers` и `skill_stats`, включает Row Level Security, добавляет политики доступа, индексы и триггеры `updated_at`.

## Применение миграции

Выберите один способ:

1. Откройте SQL Editor в панели своего проекта Supabase, скопируйте туда содержимое файла миграции и запустите запрос.
2. Если проект уже связан с Supabase CLI, выполните из корня проекта:

   ```bash
   supabase db push
   ```

После применения проверьте в Table Editor наличие четырёх таблиц и включённый RLS для каждой из них.

Политики разрешают ролям `authenticated` и `anon` читать, создавать и изменять только строки, для которых идентификатор владельца совпадает с `auth.uid()`. Обычный неавторизованный запрос получает `null` из `auth.uid()` и доступа к строкам не имеет. Анонимный пользователь, созданный через Supabase Anonymous Sign-Ins, получает собственный UID и работает только со своими данными.

Миграция не добавляет политики удаления. Ключ `service_role` обходит RLS, поэтому его нельзя использовать во frontend-коде.
